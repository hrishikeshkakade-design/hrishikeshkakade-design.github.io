01 · Overview

A shared language for a product built on tables, charts and decisions.

OneLens helps teams understand and reduce cloud spend. Most screens are dense: stats, trend charts, long tables, filters and set-up flows. The library gives every one of those screens the same structure, the same controls and the same rules for colour and status.

It covers the full stack of the product UI: semantic colour tokens for Light and Dark, an Inter type scale, spacing, radius and elevation, 68 components from buttons to wizards, three icon sets and the layout recipes for each page type.

68coded components, from buttons to set-up wizards
2,801icons across line, solid and full-colour sets
161colour tokens, defined for Light and Dark
My role

Senior Product Designer. I defined the foundations and component set, documented usage and page patterns, and kept the Figma library and its coded mirror in sync.

Who it serves

Designers composing new OneLens flows, and engineers building them from the same tokens and component names.

02 · The challenge

Many modules, one product.

OneLens spans cost analytics, savings, recommendations, governance, integrations and settings. Each area is data-heavy, and each was designed for a different job.

Without shared foundations, the same idea drifts: a status colour means one thing in a table and another in a chart, toolbars order their controls differently, and every new page starts from scratch. The library needed to make the right choice the easy one, for designers in Figma and engineers in code.

The design challenge

Give a dense, multi-module product one consistent language that holds up in both themes and maps one-to-one from Figma to code.

03 · Principles

Four rules that keep dense screens readable.

Data first, chrome second

White surfaces on a near-white canvas, separated by 1px hairlines rather than shadows. Shadows are kept for things that float: menus, pickers, toasts and modals.

Green means act or selected

The brand green is reserved for the primary button, checked controls, the selected tab and selected dates. Never decoration, never large fills.

Status is always labelled

Success, warning and error colours always travel with a word or an icon, so meaning never depends on colour alone.

Compact and consistent

Controls default to 32px and inputs to 36px, with 14px Medium text. The same heights line up across toolbars, tables and forms.

04 · Foundations

Semantic tokens, one type family and a 4px grid.

Colour

Components only use semantic tokens such as background-primary-1 or text-body-1; the primitive scales are reference only. Switching theme swaps the values behind the names, so no component needs a dark variant. Switch this page to dark mode to see it.

Surfaces, text and borders 161 colour tokens in total
Status primary-1 for ink, bg-1 / bg-2 for tints
Badge pairs ten hues, ink on tint
Chart series A–S, used in alphabetical order
Contrast is documented, not hidden

A few values come straight from the source and fall short of AA: white on the brand green is 2.9:1, and text-body-2 on white is 2.6:1. The guidance works around them: short, 14px Medium labels on green buttons, and nothing essential in text-body-2.

Type

Inter throughout. Medium (500) is the product default, Normal (400) is for running text and Semibold (600) is for emphasis. Each size is paired with a fixed line height so rows and controls stay on the 4px grid.

Space & depth

A 4px spacing scale, a small set of radii, and shadows only for things that float.

06 · Iconography

A curated icon set, searchable and in code.

Most of the line and solid icons come from the Untitled UI icon library, curated and named for OneLens so the same name works in Figma and in code. The full-colour set collects the cloud, AI and brand marks the product needs.

07 · Page templates

Page types that assemble the same way every time.

Every OneLens page is the same stack: side nav, a 64px header, optional tabs, a sticky 68px toolbar, then content sections. The library documents seven page types; six are built here entirely from library components.

08 · Figma to code

The same names in the file and in the codebase.

Every value starts in the Figma library. Tokens are exported as data, compiled to CSS variables for both themes, and consumed by components that use Figma's own names and variant props.

Figma library

Variables, text styles, effects and components. The source of truth.

Tokens

tokens.json holds colour, spacing, radius, line and shadow values for each theme.

CSS variables

tokens.css exposes them as --text-body-1 and friends, switched by data-theme.

Components

React components with prefixed as- classes. Props mirror Figma variants.

// A Figma "Button / Green / Base" becomes:
<Button color="green" size="base" leftIcon="plus">Create Policy</Button>

// A compliance column, coloured by threshold (<60 red, <85 yellow):
{ key: 'c', label: 'Compliance', type: 'meter' }
09 · Outcome

One system from foundations to full pages.

The library gives OneLens one source for how the product looks and behaves, from a single colour token to a complete page.

Foundations

Tokens for both themes

161 colour tokens plus type, spacing, radius, line and shadow scales, defined for Light and Dark.

Components

68 coded components

Named and structured like their Figma counterparts, with props that map to variants.

Patterns

Documented page types

Layout recipes for dashboards, explorers, queues, catalogues, marketplaces and settings.

10 · What's next

What still lives only in Figma.

The library is honest about its gaps. These patterns exist in the Figma file but are not yet coded components:

  • Line, area, heat-map, tree-map, leaderboard and Sankey charts
  • The workflow builder canvas and its node cards
  • Tag input and split input buttons
  • Month, year and decade pickers
  • Saved-filter and saved-view dropdowns
  • Custom scroll bar and avatar photo placeholders
